# 案例：一块 WD5000AAKX 的完整鉴定（已脱敏）

一块 2026 年购入的二手 WDC WD5000AAKX 500GB，原生 SATA 接入，走完六阶段的实录。可作为报告模板的填写样例。

## 过程

1. **识别接入**：内核正常识别。`lsblk` 确认盘符（同机多盘，按型号+序列号锁定目标）。
2. **分区表诊断**：盘首约 1GB 全零、无分区表、无签名，盘尾留一个空 GPT 壳——敷衍擦除。
3. **SMART 取证**：`Power_On_Hours=0`，计数器全套归零，**自检日志和扩展错误日志也被清空**（深度清零，真实小时数不可考）。
4. **残留数据**：1GB~450GB 大量非零。无 LVM/NTFS/ext 有效超级块；`strings` 抽样发现 glibc 错误表（Linux 系统区）、国产桌面系统与办公套件字符串、电商平台会话缓存（时间戳换算为 2022 年）——画像为信创桌面 PC，轻载办公使用数年。
5. **坏道验证**：`badblocks -sv` 全盘 500GB，**0 坏块 0 错误**。
6. **处置**：因残留数据含他人隐私，先整盘 `dd` 写零（约 83 分钟，全程 100~128MB/s 平滑无坑），终检 SMART 三项全零 → 读写双绿。随后写入身份档案，进入 NAS 存储池服役。

## 报告

```
型号/序列号/固件/容量:  WDC WD5000AAKX-08U6AA0 / WD-WCC2EVZ4xxxx / 19.01H19 / 500GB
接入方式:              原生 SATA 6Gbps
分区表状态:            主表被抹（盘首 1GB 全零），尾部留空 GPT 壳
SMART 判决:            实锤清零（PoH=0、计数器全归零、自检/错误日志均被清空）
真实履历:              小时数不可考；2022 年仍在使用的国产桌面系统办公机，
                       按办公负载估 6000-7500 小时轻载
残留数据:              ~450GB（系统区 + 缓存 + 高熵用户数据），已整盘写零销毁
坏道验证:              全盘只读扫 500GB，0 坏块；整盘写零平滑，终检三项全零
处置建议:              读写双绿的优质清零盘，可入池（非关键数据用途）
档案处置:              文件版 + 评估日 SMART 快照（本盘进池后才想起 HPA，
                       顺序铁律见 references/hpa-archive.md）
```

## 教训

- HPA 身份档案要**先于进池**埋入盘尾；进池后盘尾归阵列数据区，再无安全的埋档位置。
- 深度清零（连自检/xerror 都清）时，真实盘龄只能靠盘面残留数据推断，`strings` 画像是最低成本的途径。
